# 120_LINE文章直し（文章なおし）

打った文を Gemini に直してもらい、そのまま LINE で送るための、スマホ用の小さなアプリ。

## 使い方
1. アプリを開く（入力欄にカーソルが当たった状態で開く）→ 「送りたい文」に打つ。「🎤 声で入力」を押して話してもよい
2. 直し方のボタン（面白く・ていねい・やわらかく・短く・誤字だけ）を押す → 2〜4秒で「直した文」に出る
3. 気に入らなければ「もう一回」（前と違う言い回しで出し直す）。手で少し直してもよい
4. 「LINEで送る」→ LINE の送る相手を選ぶ画面が開く（「コピー」で貼り付けてもよい）

ほかのアプリで文を選んで「共有」→「文章なおし」を選ぶと、その文が入った状態で開く（ホーム画面に置いたあと）。

開き直すと、文は消えてまっさらになる（1分以上ほかのアプリにいたとき）。1分より短く戻ったときは残る。

## 最初の準備
- Gemini の鍵（API キー）を、Google AI Studio で作り、アプリ下の「設定」に入れて保存する
- 鍵はそのスマホの中（localStorage）にだけ置く。ファイル・URL には書かない
- 無料の鍵だと、送った文が Google のサービス改善に使われることがある

## PC で試す
```
python D:\99_AIソフト\88_LiveServer_自作\live_server.py "D:\99_AIソフト\120_LINE文章直し" 5590
```
→ http://localhost:5590/ を開く。localhost では、しまう仕組み（sw.js）を使わない（古い画面が残らないように）。

## スマホに入れるには
- 公開先：https://yoshida55.github.io/line-naoshi/ （GitHub Pages・リポジトリ yoshida55/line-naoshi は公開）
- スマホの Chrome で開き、メニューの「ホーム画面に追加」（またはアプリをインストール）
- 直したら、一斉プッシュで送れば1分ほどで公開先も新しくなる
- 送ったあとは、アプリを開き直す（1分以上ほかの画面にいてから戻る）と、新しい版に入れ替わる（ver.6〜）
- ver.5 以前の版から ver.6 に上がるときだけは、アプリを履歴から消して（上にスワイプ）開く、を2回する。古い sw.js が、しまってある古い画面を出すため

## ファイル
| ファイル | 役目 |
|---|---|
| index.html / style.css | 画面 |
| app.js | Gemini に頼む・LINE へ渡す・鍵を残す・開き直したら文を消す |
| manifest.json | ホーム画面のアプリにするための名札（「共有」から受け取る設定もここ） |
| sw.js | いつもネットから新しい版を取り、電波が無いときだけ、しまってある画面を出す仕組み |

## 決めたこと
- モデルは `gemini-flash-latest`（いつも新しい flash を指す名前）。考える時間を切っている（`thinkingBudget: 0`）。オンだと待ちが長くなる
- 鍵はヘッダー（`x-goog-api-key`）で送る。URL には入れない
- 直しすぎない。書いた人の口調・長さ・言っていることを残し、元に無い文は足さない。「面白く」は1か所だけクスッとさせる（2026-11-25：最初の版は「仕事という名のラスボス」「宴を始めててー！」のように加工しすぎて、使いづらいと言われた。ユーザー「元の文からちょっとだけ面白くなればいいだけの程度の時もある」「文章を変えすぎは、おれじゃないみたい」）
- 「！」と絵文字は足してよい（ユーザー「！とか絵文字はいいんだけど」）。ただし「ていねい」には絵文字を足さない
- 言っていることを1つも落とさない、と決まりに書く。書かないと「やわらかく」で「ほかの日にして」が消えた
- 「面白く」は、元の言葉をほぼそのまま使い、語尾か1語と「！」・絵文字でノリを出す。話している物を別の物にたとえない（2026-11-25：「今日天気いいね」が「今日の太陽、やる気出しすぎじゃない？」になり、変わりすぎと言われた。直したあとは「今日天気良すぎん！？☀️」）
- 開き直したら文を消す（ver.4〜）。ver.3 までは打ちかけの文を残していたが、ユーザーに「基本、開き直した時に文字消えるようにしてほしい」と言われた。スマホはアプリを閉じても裏で動き続け、ページが読み込み直されないので、画面から外れていた時間で見分ける（app.js の `CLEAR_AFTER`＝1分。ほかのアプリを少し見て戻ったときは消さない）
- 開いたら入力欄にカーソルを当てる（ver.5〜・ユーザー「起動した時は入力ボックスに入力カーソルを当てるようにして」）。共有で文が来たときだけは当てない（キーボードが出て、直し方のボタンが隠れるため）。スマホの Chrome は、ボタンを押さずに開いたときはキーボードを出さないことがある
- 「🎤 声で入力」ボタン（ver.5〜・ユーザー「音声入力ボタンもあるといいかもしれない」）。Chrome の音声認識（Web Speech API）を使う。話し終わると自分で止まり、前に打ってあった文のあとに足す。使えない端末ではボタンを出さない
- 画面の右上に版の番号を出す（app.js の `VERSION`）。直して公開するたびに1つ上げる。スマホで新しい版になったかを、ここで見分ける
- 送ってもスマホが前の版のままだった（ver.5 を送ったのに ver.4 で、声のボタンが無かった）。原因は3つ。①sw.js が「しまった画面をすぐ出し、裏で取り替える」形で、新しい版が出るまで2回開く必要があった ②公開先（GitHub Pages）が「10分は使い回してよい」（`max-age=600`）と返すので、裏で取り替えるときも古い物が来た ③アプリは裏で動き続け、開き直してもページが読み込み直されない。直し方（ver.6〜）：sw.js は毎回ネットに「変わった？」と聞く（電波が無いときだけしまった物）、返すときに札を「毎回確かめて」（`no-cache`）に付けかえる、1分以上たって開き直したら app.js の `VERSION` を見比べ、新しければ読み込み直す（app.js の `checkNewVersion`。共有で文が届く途中を邪魔しないよう1.5秒待つ）
- 入力欄の薄い字は「ここに打つ」だけ（ver.6〜）。「声でもOK」と書いていたら、声のボタンが無い古い版でも、声で入れられると思わせた
- 声で入力は、聞き始め（「🎤 聞いています」）と止まった理由（聞き取れなかった・マイクが使えない など）を、いつも「直した文」の上の知らせ欄に出す（ver.6〜）。何も出ないと、押しても反応しないように見える
